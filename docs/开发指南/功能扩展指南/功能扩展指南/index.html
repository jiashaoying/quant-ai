    引言¶

    本指南面向希望扩展系统能力的开发者，覆盖以下主题： - 新增量化策略的完整流程（继承基类、实现信号生成、注册元数据、参数配置） - 扩展数据源（实现获取接口、异常降级、统一数据格式） - 开发自定义可视化组件（React 组件结构、Recharts 集成、状态管理） - 提供最佳实践、常见陷阱与解决方案 - 明确变更影响边界与前后端同步更新要求

    项目结构¶

    本项目采用前后端分离架构： - 后端 FastAPI 提供回测 API，封装策略引擎与多数据源管理器 - 前端 React + Recharts 提供表单输入与结果可视化

    核心组件¶

    • 策略引擎：定义 BaseStrategy 抽象基类与多种内置策略；提供 get_available_strategies 与 create_strategy 工厂方法
    • 数据源管理器：统一获取 OHLCV 数据，支持自动选择与降级到模拟数据
    • 回测 API：串联数据获取、策略实例化、信号生成与回测执行，返回包含指标、交易记录、资金曲线等结果
    • 前端表单与结果：用户输入策略与参数，展示回测结果与图表

    详细组件分析¶

    一、新增量化策略（继承 BaseStrategy）¶

    目标：在不改动现有逻辑的前提下，通过继承基类、实现信号生成、注册元数据与工厂方法，完成新策略接入。

    步骤概览 1. 继承 BaseStrategy 并实现 generate_signals 2. 在 get_available_strategies 中注册策略元数据（id、name、description、parameters） 3. 在 create_strategy 中增加分支以创建新策略实例 4. 在前端 BacktestForm 中为新策略添加参数表单控件

    图表来源 - backend/app/strategies/engine.py:17-25 - backend/app/strategies/engine.py:28-504

    关键要点 - 基类约定 - init 接收 name 与 parameters，供后续回测结果展示 - generate_signals 必须返回包含 signal 与 position 列的 DataFrame - 策略元数据 - id 作为唯一标识，用于 create_strategy 与前端参数渲染 - parameters 描述每个参数的类型、默认值、取值范围，便于前端校验与渲染 - 工厂方法 - create_strategy 根据 strategy_id 构造具体策略实例，并透传参数

    新增策略完整流程 - 在 strategies/engine.py 中新增子类，实现 generate_signals - 在 get_available_strategies 追加该策略的元数据条目 - 在 create_strategy 增加对应分支 - 在 frontend/src/components/BacktestForm.tsx 中为该策略新增参数输入控件（与元数据 fields 对齐）

    最佳实践 - 保持 generate_signals 对输入数据的不可变性（使用副本），避免副作用 - 合理处理 NaN/Inf，确保下游回测引擎稳定 - 为复杂策略提供清晰的 docstring 与参数说明，便于前端自动生成表单

    常见陷阱与解决 - 忘记在 get_available_strategies 注册：导致前端无法显示参数面板 - 忘记在 create_strategy 注册：导致运行时 Unknown strategy 错误 - 未对齐前端参数字段名：导致参数无法正确传入策略构造函数

    二、扩展数据源（实现获取接口、异常降级、统一格式）¶

    目标：在不破坏现有自动切换与降级机制的前提下，新增一个数据源实现。

    当前能力 - DataSourceManager.get_stock_data 支持 auto/tencent/yfinance/akshare/baostock/mock - _auto_fetch 按市场类型优先尝试多个数据源，失败则降级至模拟数据 - 所有实现均输出统一的 OHLCV 列名：Date/Open/High/Low/Close/Volume

    flowchart TD
Start(["get_stock_data"]) --> CheckSource{"source == 'auto'?"}
CheckSource --> |是| Auto["_auto_fetch()"]
CheckSource --> |否| Dispatch["分发到具体实现"]
Auto --> TryTencent["尝试腾讯财经"]
TryTencent --> TryYF["尝试 YFinance"]
TryYF --> TryAK["尝试 AKShare(A股)"]
TryAK --> TryBS["尝试 BaoStock(A股)"]
TryBS --> Fallback["兜底: 模拟数据"]
Dispatch --> Return["返回 (DataFrame, source)"]
Fallback --> Return

    图表来源 - backend/app/services/data_source_manager.py:14-109

    新增数据源步骤 1. 在 data_source_manager.py 中新增私有方法 _fetch_xxx(symbol, start_date, end_date, period)，返回统一格式的 DataFrame 2. 在 get_stock_data 的 dispatch 分支中添加新 source 枚举 3. （可选）在 _auto_fetch 中插入新的尝试顺序，或仅在指定 source 下可用 4. 在前端 DATA_SOURCES 列表中添加新选项（label/desc/icon） 5. 在 BacktestResult 的数据源名称映射中补充新 source 的显示名称

    统一数据格式规范 - 列名：Date/Open/High/Low/Close/Volume - Date 为 datetime 类型 - 数值列均为 float - 空数据时返回空 DataFrame，由上层进行降级处理

    异常与降级 - 各数据源实现应捕获异常并返回空 DataFrame 或抛出可识别异常 - _auto_fetch 会依次尝试，最终兜底 mock 数据 - 前端通过 is_mock 标记提示“模拟数据”

    性能与可扩展性¶

    • 策略计算
    • 尽量使用向量化操作（pandas/numpy），避免逐行循环
    • 对长序列注意滚动窗口计算的内存占用，必要时分块处理
    • 数据获取
    • 网络请求设置超时与重试；对第三方库导入做 try/except 保护
    • 大区间数据拉取考虑分页或增量更新
    • 前端渲染
    • 大数据量图表使用采样或虚拟滚动
    • 避免在渲染函数中进行昂贵计算，使用 useMemo/useCallback 缓存

    故障排查¶

    常见问题与定位路径 - Unknown strategy 错误 - 检查是否在 create_strategy 中注册了该 strategy_id - 检查前端是否传入了正确的 strategy_id - 参考：backend/app/strategies/engine.py:600-656 - 数据为空或全部为模拟数据 - 检查 _auto_fetch 的降级日志与 is_mock 标志 - 确认网络与依赖安装（如 akshare/baostock） - 参考：backend/app/services/data_source_manager.py:56-109 - 前端参数未生效 - 核对 BacktestForm 中的参数键名是否与策略构造函数一致 - 核对 get_available_strategies 中 parameters 的字段名 - 参考：frontend/src/components/BacktestForm.tsx:111-504, backend/app/strategies/engine.py:506-597 - 图表不显示或数据错位 - 检查 equityData 的 date/equity/price 字段是否正确映射 - 参考：frontend/src/components/BacktestResult.tsx:35-43
